VLAN — Segmentation réseau
★★★ Très fréquent ▾
Mots déclencheurs : VLAN segmenter isoler commutateur 802.1Q trunk / access plan d'adressage
TYPE 1 Justifier la segmentation en VLANs
Structure : Définition → Avantages (3 axes : sécurité, performance, gestion) → Application au cas
Phrase type « La segmentation en VLANs permet d'isoler les flux réseau par service (administration, production, invités). Cela limite la propagation d'une attaque, réduit le domaine de diffusion et facilite l'application de règles de filtrage ciblées au niveau du pare-feu. »
Ne pas confondre VLAN (couche 2) et sous-réseau IP (couche 3). Un VLAN est une séparation logique sur commutateur ; la communication inter-VLAN nécessite un routeur ou pare-feu.
TYPE 2 Attribuer des VLANs (tableau)
Structure : Remplir le tableau avec VLAN ID, Nom, Réseau IP, Plage DHCP, Passerelle
Conseil Associer 1 service = 1 VLAN = 1 sous-réseau. Ex : VLAN 10 – Admin – 192.168.10.0/24 – GW 192.168.10.1. Garder VLAN 1 inutilisé (défaut = risque). → Voir tableau modèle ↓
TYPE 3 Configurer un port Access / Trunk
Access = 1 VLAN, équipement terminal (PC, imprimante)
Trunk = plusieurs VLANs taggés (802.1Q), entre commutateurs ou vers routeur/pare-feu
Commandes Cisco type Access : switchport mode access / switchport access vlan 10
Trunk : switchport mode trunk / switchport trunk allowed vlan 10,20,30

Pare-feu / NAT / Table de filtrage
★★★ Très fréquent ▾
Mots déclencheurs : pare-feu firewall NAT DMZ règle de filtrage ACCEPT / DROP iptables politique de sécurité
TYPE 1 Expliquer le rôle du pare-feu
Phrase type « Le pare-feu contrôle les flux réseau entrants et sortants en appliquant des règles de filtrage basées sur l'adresse IP source/destination, le port et le protocole. Il protège les ressources internes contre les accès non autorisés en appliquant le principe du moindre privilège : tout ce qui n'est pas explicitement autorisé est refusé. »
TYPE 2 Remplir / compléter une table de filtrage
Colonnes à connaître : N° | IP Source | IP Destination | Protocole | Port Dest. | Action (ACCEPT/DROP) | Commentaire

Méthode de lecture de l'énoncé :
  1. Identifier qui communique avec qui (source → destination)
  2. Identifier quel service (port 80=HTTP, 443=HTTPS, 22=SSH, 25=SMTP, 53=DNS, 3389=RDP...)
  3. Appliquer le principe default DENY en dernière règle
  4. Pour le trafic de retour : ajouter une règle RELATED/ESTABLISHED ou stateful
Exemple de règle | 1 | LAN (192.168.1.0/24) | Serveur Web (10.0.1.10) | TCP | 443 | ACCEPT | Accès HTTPS interne
| 2 | Internet (0.0.0.0/0) | Serveur Web (10.0.1.10) | TCP | 443 | ACCEPT | Accès HTTPS public
| 99 | * | * | * | * | DROP | Règle par défaut
La règle par défaut (DEFAULT DENY) doit TOUJOURS être la dernière. Sans elle, tout traffic non listé serait autorisé.

→ Voir tableau modèle complet ↓

TYPE 3 Expliquer le NAT / PAT
Phrase type « Le NAT (Network Address Translation) traduit les adresses IP privées en adresse publique. Le PAT (Port Address Translation) permet à plusieurs machines internes de partager une seule IP publique en différenciant les connexions par le numéro de port source. Cela masque la topologie interne et économise les adresses IPv4. »
TYPE 4 Justifier la mise en place d'une DMZ
Phrase type « La DMZ (Zone Démilitarisée) est un réseau intermédiaire entre Internet et le LAN interne. Les serveurs accessibles depuis Internet (web, mail, DNS) y sont placés. Ainsi, si un serveur est compromis, l'attaquant ne peut pas accéder directement au réseau interne : il doit franchir un second pare-feu. »

RAID — Tolérance aux pannes stockage
★★☆ Fréquent ▾
Mots déclencheurs : RAID tolérance aux pannes disque dur sauvegarde disponibilité données redondance
TYPE 1 Choisir et justifier un niveau RAID
Structure : Besoin (performance / tolérance / coût) → Niveau adapté → Justification
Phrase type — Recommandation RAID 5 « Pour un serveur de fichiers nécessitant un bon équilibre entre performance, disponibilité et espace utilisable, je recommande le RAID 5 : il tolère la panne d'un disque et offre (N-1) × capacité d'un disque en espace utile. En cas de panne, les données sont reconstituées grâce à la parité répartie. »
RAID ≠ sauvegarde ! Le RAID protège contre la panne matérielle, pas contre la suppression accidentelle ou le ransomware. Toujours coupler RAID + sauvegarde externe.

→ Voir tableau comparatif RAID ↓

TYPE 2 Calculer l'espace utile
Formules :
RAID 0 : N × capacité disque (aucune tolérance)
RAID 1 : 1 × capacité disque (miroir sur 2)
RAID 5 : (N−1) × capacité (parité répartie, N ≥ 3)
RAID 6 : (N−2) × capacité (double parité, N ≥ 4)
RAID 10 : (N/2) × capacité (miroir + stripe)
Exemple 4 disques de 2 To en RAID 5 → (4-1) × 2 = 6 To utiles. Tolérance : 1 disque en panne.

Attaques & Contre-mesures
★★★ Très fréquent ▾
Mots déclencheurs : attaque menace vulnérabilité phishing DDoS ransomware SQL injection MITM contre-mesure
TYPE 1 Identifier et décrire une attaque
Structure : Nom → Principe → Impact → Exemple concret
Phrase type — Phishing « Le phishing est une attaque par ingénierie sociale où l'attaquant usurpe l'identité d'un organisme de confiance (banque, DSI) par e-mail pour récupérer des identifiants. Contre-mesure : sensibilisation des utilisateurs, filtre anti-spam, authentification MFA. »
Phrase type — Ransomware « Un ransomware chiffre les fichiers de la victime et exige une rançon. Il se propage souvent via une pièce jointe malveillante. Contre-mesures : sauvegardes hors ligne (règle 3-2-1), antivirus à jour, segmentation réseau pour limiter la propagation. »

→ Voir tableau attaques / contre-mesures ↓

TYPE 2 Proposer un plan de contre-mesures
Structure : Prévention → Détection → Réaction (les 3 axes de la sécurité)
Phrase type « Pour se protéger contre cette menace, il convient d'agir sur trois axes : prévention (mise à jour des correctifs, durcissement OS, sensibilisation), détection (IDS/SIEM, supervision des logs), et réaction (plan de reprise d'activité, isolation du poste infecté, restauration depuis sauvegarde saine). »

ITIL — Gestion des services informatiques
★★☆ Fréquent ▾
Mots déclencheurs : ITIL incident problème changement GLPI ticket SLA helpdesk service desk
TYPE 1 Différencier Incident / Problème / Changement
Définitions ITIL Incident : interruption ou dégradation non planifiée d'un service. Objectif : restaurer le service le plus vite possible (workaround acceptable).

Problème : cause inconnue d'un ou plusieurs incidents récurrents. Objectif : identifier la cause racine (Root Cause Analysis) et éliminer le problème.

Changement : modification planifiée de l'infrastructure. Doit passer par un processus de validation (CAB – Change Advisory Board).
Un incident se traite VITE (workaround). Un problème se traite bien (analyse de fond). Ne pas les confondre.
TYPE 2 Expliquer un SLA
Phrase type « Le SLA (Service Level Agreement) est un accord entre le prestataire IT et le client qui définit le niveau de service garanti : temps de réponse, taux de disponibilité (ex : 99,9 %), plages horaires de support. Il fixe les pénalités en cas de non-respect et constitue un engagement contractuel. »
TYPE 3 Décrire le cycle de vie d'un ticket GLPI
Nouveau → Attribué → En cours → En attente → Résolu → Clos
Phrase type « Dans GLPI, chaque incident est tracé sous forme de ticket. À l'ouverture, le ticket est qualifié (urgence × impact = priorité). Il est attribué à un technicien, qui documente ses actions jusqu'à résolution. Le ticket est clos après validation par l'utilisateur. »

Chiffrement / PKI / Certificats
★★★ Très fréquent ▾
Mots déclencheurs : chiffrement PKI certificat SSL/TLS clé publique / privée HTTPS VPN signature numérique AES / RSA
TYPE 1 Distinguer chiffrement symétrique / asymétrique
Phrase type « Le chiffrement symétrique (ex : AES-256) utilise la même clé pour chiffrer et déchiffrer : il est très rapide mais pose un problème d'échange de clé. Le chiffrement asymétrique (ex : RSA-2048) utilise une paire clé publique / clé privée : la clé publique chiffre, seule la clé privée déchiffre. TLS combine les deux : asymétrique pour l'échange de clé, symétrique pour le chiffrement des données. »

→ Voir tableau comparatif ↓

TYPE 2 Expliquer le fonctionnement d'un certificat SSL/TLS
Phrase type « Un certificat SSL/TLS est un fichier numérique signé par une Autorité de Certification (AC). Il contient la clé publique du serveur, son identité et la durée de validité. Lors d'une connexion HTTPS, le navigateur vérifie la signature de l'AC pour s'assurer de l'authenticité du serveur. »
TYPE 3 Décrire l'infrastructure PKI
Composants : AC racine (Root CA) → AC intermédiaire → Certificat final
Phrase type « Une PKI (Infrastructure à Clés Publiques) est constituée d'une Autorité de Certification racine qui signe les certificats des ACs intermédiaires, lesquelles signent les certificats des entités finales (serveurs, utilisateurs). La chaîne de confiance permet à tout client de vérifier l'authenticité d'un certificat jusqu'à l'AC racine de confiance. »

WiFi — Sécurité sans-fil
★★☆ Fréquent ▾
Mots déclencheurs : WiFi WPA2 / WPA3 RADIUS portail captif 802.1X réseau invité SSID point d'accès
TYPE 1 Choisir entre WPA2-Personal et WPA2-Enterprise
Phrase type « WPA2-Personal (PSK) utilise un mot de passe partagé : simple mais peu sûr en entreprise car tout le monde connaît la clé. WPA2-Enterprise utilise le protocole 802.1X avec un serveur RADIUS : chaque utilisateur s'authentifie avec ses propres identifiants (login/mot de passe ou certificat). C'est la solution recommandée en entreprise car elle permet une gestion individuelle des accès et une traçabilité. »
TYPE 2 Expliquer le portail captif
Phrase type « Le portail captif est une page web d'authentification qui s'affiche automatiquement quand un utilisateur se connecte à un réseau (ex : WiFi invité). Avant l'authentification, tout trafic est bloqué et redirigé vers cette page. Il permet de contrôler et tracer l'accès Internet (obligation légale HADOPI pour les lieux publics). »
TYPE 3 Sécuriser un réseau WiFi invité
Phrase type « Le réseau WiFi invité doit être isolé du LAN entreprise (VLAN dédié), avec accès uniquement à Internet. Un portail captif assure l'authentification et la traçabilité. Des règles de pare-feu bloquent toute communication vers le réseau interne. »

Supervision / SNMP / Nagios
★★☆ Fréquent ▾
Mots déclencheurs : supervision SNMP Nagios Zabbix alerte sonde disponibilité MIB trap
TYPE 1 Justifier la mise en place d'un système de supervision
Phrase type « La supervision réseau permet de surveiller en temps réel la disponibilité et les performances des équipements (serveurs, commutateurs, routeurs). Elle génère des alertes en cas d'anomalie (surcharge CPU, espace disque critique, service down) permettant une intervention avant l'impact utilisateur. »
TYPE 2 Expliquer SNMP v3 vs v1/v2
Phrase type « SNMP v1 et v2 transmettent les informations en clair avec une communauté en texte brut (ex : « public ») — facilement interceptable. SNMP v3 apporte l'authentification (SHA/MD5) et le chiffrement (AES/DES) des échanges. En entreprise, seul SNMP v3 est recommandé. »
SNMP v2c n'ajoute pas la sécurité par rapport à v1 ; seul SNMP v3 est sécurisé.
TYPE 3 Différencier polling et trap SNMP
Polling (requête GET) : le serveur interroge régulièrement les équipements → proactif mais génère du trafic
Trap : l'équipement envoie une alerte immédiatement quand un événement survient → réactif, moins de trafic
Phrase type « En production, on combine les deux : le polling surveille les métriques de base à intervalle régulier, et les traps remontent instantanément les alertes critiques sans attendre le prochain cycle de polling. »

EBIOS RM — Analyse des risques
★★★ Très fréquent ▾
Mots déclencheurs : EBIOS risque vraisemblance gravité bien support source de risque scénario d'attaque traitement du risque
TYPE 1 Définir EBIOS RM et ses 5 ateliers
Phrase type « EBIOS Risk Manager est la méthode nationale (ANSSI) d'analyse de risques cybersécurité. Elle s'articule en 5 ateliers : 1) Cadrage et socle de sécurité → 2) Sources de risque → 3) Scénarios stratégiques → 4) Scénarios opérationnels → 5) Traitement du risque. »
TYPE 2 Calculer et positionner un risque (matrice)
Méthode : Évaluer la vraisemblance (probabilité, 1→4) × la gravité (impact, 1→4) → placer sur la matrice → décider du traitement
Traitement du risque Accepter : risque faible, coût de traitement supérieur au risque
Réduire : mettre en place des mesures de sécurité
Transférer : souscrire une assurance cyber
Éviter : supprimer l'activité génératrice du risque

Active Directory / GPO
★★☆ Fréquent ▾
Mots déclencheurs : Active Directory GPO domaine OU groupe contrôleur de domaine LDAP authentification centralisée
TYPE 1 Justifier l'utilisation d'Active Directory
Phrase type « Active Directory centralise l'authentification et la gestion des ressources du domaine. Les utilisateurs s'authentifient une seule fois (SSO – Single Sign-On) et accèdent à leurs ressources selon leurs droits. Les GPO permettent d'appliquer des paramètres de sécurité (politique de mot de passe, verrouillage d'écran, restriction des logiciels) à des groupes d'utilisateurs ou d'ordinateurs. »

Exemple de structure Domaine : entreprise.local

Groupe : GRP_Compta → membres : tous les comptes du service Comptabilité

IDS / IPS / Snort
★☆☆ Moins fréquent ▾
Mots déclencheurs : IDS IPS Snort intrusion détection signature anomalie
TYPE 1 Différencier IDS et IPS
Phrase type « Un IDS (Intrusion Detection System) analyse le trafic réseau et génère des alertes en cas de détection de comportement suspect, sans agir sur les flux. Un IPS (Intrusion Prevention System) peut, en plus, bloquer automatiquement le trafic malveillant. Snort peut fonctionner en mode IDS (passif) ou IPS (inline). »
Un IDS ne bloque rien : il détecte et alerte. C'est l'IPS qui bloque. Le choix dépend du risque de faux positifs.
TYPE 2 Lire / écrire une règle Snort
Syntaxe : action protocole IP_src port_src → IP_dst port_dst (options)
Exemple alert tcp any any → 192.168.1.0/24 22 (msg:"Tentative SSH brute-force"; threshold:type both, track by_src, count 5, seconds 60; sid:1000001;)

→ Alerte si une IP tente + de 5 connexions SSH en 60s vers le LAN.

RGPD / Conformité
★★☆ Fréquent ▾
Mots déclencheurs : RGPD données personnelles DPO consentement droit à l'oubli violation de données CNIL registre des traitements
TYPE 1 Identifier les obligations RGPD
Phrase type « Le RGPD impose plusieurs obligations : tenir un registre des traitements, recueillir le consentement explicite des personnes concernées, respecter les droits des personnes (accès, rectification, effacement, portabilité), et notifier la CNIL sous 72h en cas de violation de données. »
TYPE 2 Rôle du DPO
Phrase type « Le DPO (Data Protection Officer / Délégué à la Protection des Données) est le responsable de la conformité RGPD au sein de l'organisation. Il conseille les équipes, sensibilise le personnel, réalise les analyses d'impact (PIA), et est l'interlocuteur de la CNIL. Sa nomination est obligatoire pour les organismes publics et certains traitements à grande échelle. »
